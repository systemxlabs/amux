# amux — Product Requirements Document

> 本文档描述 amux 的**完整产品**，不区分优先级。agent 依据本文档实现代码；本文档变更时，代码随之同步更新（见 AGENTS.md「文档与实现」）。

## 1. 背景与目标

当前的 agentic coding 工具（Codex、Claude Code 等）集中在 harness 层——模型调用、工具执行、对话管理。在此之上缺少一个控制平面：跨机器调度不同 harness、会话的断开与恢复、多会话管理。

目标用户：日常使用 agentic coding 工具完成开发任务的工程师。工作中同时使用 IDE、浏览器、终端，amux 作为控制平面与这些工具配合，不替代它们。

典型工作环境：用户拥有本机 PC 和远程机器。本机负责浏览器操作（如 UI 测试、网页交互）、轻量开发任务；远程机器负责部署、编译等重任务。amux 统一调度两端的 harness。

核心体验：用户打开 amux，自动恢复所有机器的活跃会话列表；选中会话进入多面板视图，实时看到 agent 交互；随时关闭应用，agent 继续运行；重新打开自动重连，常用操作一键触发，无需打字。

## 2. 用户场景

**创建与管理会话**：用户在机器 A 上启动一个 codex 会话，工作目录为 `~/projects/api-server`。会话列表中出现该会话，标记为"thinking"状态。用户可以实时看到 agent 的思考过程、工具调用和输出。

**关闭后继续运行**：用户关闭 amux，机器 A 上的 agent 继续运行。用户在另一台设备上打开 amux，自动重连，跳到该会话的最新位置，可向上滚动查看关闭期间产生的输出。

**跨机器工作流**：用户在远程机器上用 codex 实现功能，完成后自动在本机用 claude code 做 code review，结果汇总展示。

## 3. 交互设计

### 3.1 主界面布局

#### 3.1.1 会话列表（左侧面板）

- 包含 harness 会话与编排 agent 会话（见 §4.10），按**最近活跃**排序
- 基于工作流创建的编排 agent 会话，其下挂载工作流所驱动的若干 agent 会话（子会话），**默认折叠**、可展开查看；子会话随父会话一起参与最近活跃排序
- 每条显示**会话标题**、agent/harness、所属机器与状态
- 底部为**设置入口**，点击打开设置浮窗

#### 3.1.2 新会话视图（未选中任何会话时）

- 一个自然语言输入框
- 选择机器与 agent（harness），并指定工作目录
- 或切换为"从工作流模板创建"——选择模板，机器与 agent 由模板步骤指定（见 §4.10）

#### 3.1.3 会话视图与输入（中间面板，选中会话后）

- 中间面板**上下分栏**：
  - **上方：对话流**——只展示用户消息与 agent 输出的消息气泡（输出为完整消息，非流式），弹性占满剩余空间
  - **下方：会话活动**——只展示**正在进行的活动**（一条或无）：当前 thinking / tool call 的实时状态，空闲时不显示；完整历史在右侧面板查看（见 3.1.4）
- 底部：输入区；输入区上方为快捷按钮栏（Commit & Push、Submit PR 等）
- 对话流右侧边缘：竖向排列的悬浮按钮（diff、会话详情、会话活动历史），点击展开对应的右侧面板

#### 3.1.4 上下文面板（右侧面板）

- 默认折叠，由悬浮按钮触发展开
- **diff 视图**：点击 diff 按钮弹出工作区 diff 视图（workspace 不是 git 仓库时不提供 diff 按钮）
- **会话详情**: 点击会话详情按钮弹出会话信息
- **会话活动**：点击会话活动按钮弹出会话活动，视图上下滚动查看更久的会话活动

### 3.2 输入

- 输入区支持多行文本，可拖拽文件、粘贴图片作为上下文
- 支持语音输入
- 支持 @ 引用文件或目录作为上下文

### 3.4 设置页面

- 全局配置集中在**设置浮窗**，经左侧面板底部的设置入口打开；浮窗以半透明遮罩盖在主界面之上，内部为**分类导航侧边栏 + 右侧设置内容**（类似系统设置），点遮罩或关闭按钮收起
- 设置浮窗分类：
  - **机器管理**：接入 / 移除机器、连接配置（地址、token）、harness 默认模型
  - **编排 agent**：内置编排 agent（见 §4.10）的 API 配置——供应商/后端（backend）、Base URL、API key
  - **通知**：通知开关与触发条件（工作结束 / 出错 / 长时间无响应）
  - **快捷按钮**：按钮自定义（增删按钮、修改提示词）
  - **Skills**：Skills 注册表
  - **工作流模板**：模板管理（查看 / 新建 / 编辑 / 删除）；模板是可复用的自然语言工作流描述（见 §4.10）

## 4. 功能需求

### 4.1 会话管理

- 在多台机器上创建 agent 会话，新建会话时指定工作目录，agent 即在该目录启动
- 会话有**标题**：默认由首条指令/目标自动生成（简短摘要），用户可随时修改
- 支持 codex、claude code、kimi code 等主流 agent harness
- 展示 agent 输出（完整消息，非流式）；进行中显示工作状态，思考过程、工具调用等详细活动在会话活动面板查看（见 4.3）
- 可在 agent 工作过程中发送新指令干预其行为（steer）
- 可随时取消当前工作
- 结束会话后对话历史保留，可恢复继续
- 可永久删除会话（历史一并移除，不可恢复）
- 关闭应用后 agent 在后台继续运行，重新打开自动重连恢复
- 浏览所有机器上的所有活跃会话（含编排 agent 会话），按机器、harness 类型或编排 agent 筛选

### 4.2 会话历史

- 会话对话内容持久化存储（用户输入、agent 输出）；详细活动随会话保留，可在会话活动历史（右侧面板，见 3.1.4）回溯
- 用户可滚动回溯任意历史位置
- 回溯期间新事件正常收取但不强制滚动到底，用户可一键跳回底部
- 支持从历史中选中内容复制
- 重连后自动拉取持久化历史，关闭期间产生的输出不丢

### 4.3 会话活动

- 会话的详细活动展示在两处，互补：
  - 中间面板**下方的会话活动面板**（见 3.1.3）：只展示**正在进行的活动**（一条或无）——当前 thinking / tool call 的实时状态，空闲时不显示
  - 右侧面板的**会话活动历史**（见 3.1.4）：持久化的完整活动历史，可上下滚动查看更久的活动
- 活动按时间线排列，可查看每次活动的细节（如工具调用的参数与结果、思考内容、压缩摘要）
- 下方面板反映实时状态；历史视图从持久化数据回溯

### 4.4 设置：机器管理

机器管理位于设置页面（见 3.4），不在主界面操作：

- 每台机器都可接入 amux，注册后即可连接使用
- 所有机器（含桌面应用所在的本机）同等对待，不设特殊的本机路径
- 查看所有已注册机器的列表及在线状态
- 每台机器自动发现本机已安装的 agent harness
- 用户可为 harness 配置默认模型（harness 可执行路径自动发现，不手动指定）
- 同一用户可在多台设备同时打开 amux（如台式机和笔记本），多实例天然共存、互不踢出，均可查看和操作同一会话

### 4.5 通知

- 工作结束（含结束原因）、异常终止、长时间无响应时发送桌面通知
- 按会话或全局配置通知开关和触发条件
- 通知携带机器和会话信息，点击通知可直接打开对应会话

### 4.6 快捷按钮

- 预设常用操作：Commit & Push、Submit PR
- 用户可增删按钮、修改按钮对应的提示词（按钮即"发给 agent 的指令"）

### 4.7 Diff Review

- 会话中实时查看当前工作区 git diff——文件列表和行数统计
- 点击文件查看 side-by-side 或 inline diff，带语法高亮
- 对单个文件、单个 hunk 或全部变更执行 revert
- 在 diff 视图中直接对特定代码片段发起指令

### 4.8 Worktree 管理

Session 在工作目录中原地工作，不自动创建 worktree。Worktree 管理是独立功能：

- 查看任意机器上所有 git worktree 的信息：路径、分支、clean/dirty 状态
- 从分支或 commit 创建新 worktree，可同时创建关联 agent 会话
- 删除 worktree，有活跃会话时警告
- 锁定 worktree 防止误删

### 4.9 Skills 管理

- 添加 skills 时只需指定仓库 URL 和本地目录，系统只存这两项
- 会话启动时，系统将已启用的 skills 拼成 prompt 发给 agent，由 agent 执行实际的 clone/pull
- Skills 可设为全局、项目级（关联特定 git repo 的会话自动加载）、或个人级
- 每个 skills 仓库可单独启用/禁用

### 4.10 工作流

工作流是多步编排：用户用一段**自然语言**描述目标（可含步骤偏好、机器/harness 偏好、约束），由 **GUI 内置编排 agent** 解析为步骤计划并驱动执行；执行过程中用户可**随时暂停与介入**。工作流复用会话、steer、通知与多机器能力（见 §4.1 / §4.5 / §2 跨机器场景）。

- **内置编排 agent**：GUI 内置（模型可配置），只做编排、不做具体实现——把自然语言工作流拆解为步骤，为每步选择机器与 harness（或沿用用户指定），创建/复用会话并下发指令，依据各步结果决定后续步骤（含按结果分支、重试、汇总结论）；具体编码/执行仍由被调度的 harness 会话完成，不违反"不做 agent 实现"的边界（见 §6）
- **自然语言描述**：以一段自然语言描述工作流，支持 @ 引用仓库/文件/目录作为上下文（见 §3.2）；提供常用模板，如"远程机器用 codex 实现功能 → 本机用 claude code review → 汇总结果"、"提交并推送 + 创建 PR"
- **工作流模板**：常用工作流可保存为模板（名称、说明 + 自然语言描述），创建新会话/工作流时可选择"从模板创建"；模板在设置页管理（见 §3.4），支持查看 / 新建 / 编辑 / 删除
- **计划与确认**：编排 agent 先生成步骤计划（每步：动作、目标机器、harness、依赖关系），执行前在 GUI 展示，用户可确认、编辑（增删/调整步骤或目标）后执行，也可直接执行
- **执行状态**：工作流状态机——`planning`（生成计划）/ `waiting_confirm`（等待确认）/ `running`（执行中，含当前步骤与整体进度）/ `paused`（已暂停）/ `waiting_input`（等待用户决策）/ `finished` / `failed` / `cancelled`；GUI 展示计划、当前步骤、日志与进度；工作流所驱动的 harness 会话作为**子会话**挂在工作流会话下（左侧列表默认折叠，见 §3.1.1），每步可下钻查看
- **暂停与介入**（任意时刻）：
  - **暂停/继续**：随时暂停——等待当前会话的 turn 结束后不再启动下一步（优雅暂停，不打断正在执行的 agent），可随时继续
  - **介入**：暂停后修改剩余步骤、插入新步骤或调整目标（对编排 agent 下达新指令）；也可直接打开某步关联的会话手动操作（切到会话视图与 harness agent 直接对话），完成后回到工作流继续
  - **取消**：终止工作流；已下发的会话由用户选择保留运行或关闭
- **通知**：工作流完成、失败、等待确认/介入时发送桌面通知（复用 §4.5），点击可直接回到对应工作流
- **持久化与恢复**：工作流状态（描述、计划、进度、日志）持久化于 GUI 本地；GUI 关闭后，已下发的会话由各机器 server 继续运行，工作流标记为中断，GUI 重新打开后从暂停处恢复编排

## 5. 非功能需求

- **响应性**：打开应用 3 秒内恢复连接并展示会话列表；实时事件延迟不超过 500ms
- **可靠性**：关闭应用后 agent 不中断；机器重启后重新打开 amux 即可恢复会话
- **跨平台**：macOS、Linux 一级支持；Windows 二级支持
- **数据主权**：所有数据存储于自有机器，不上传至第三方服务

## 6. 边界与约束

- 不做 agent 实现，只做控制平面——amux 只是连接已有的 agent harness；GUI 内置的编排 agent 只负责工作流的拆解与调度（§4.10），不参与具体的编码/执行
- 不做 IDE 插件——amux 是独立桌面应用
- 不替代 git 工具——不提供完整的 git 操作界面，只提供常用快捷操作
- 不做代码编辑器——代码查看仅限于 diff review 场景
- 不做用户认证与权限系统——单用户工具，信任运行环境
