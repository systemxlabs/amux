# amux — Product Requirements Document

> 本文档描述 amux 的**完整产品**，不区分优先级。agent 依据本文档实现代码；本文档变更时，代码随之同步更新（见 AGENTS.md「文档与实现」）。

## 1. 背景与目标

当前的 agentic coding 工具（Codex、Claude Code 等）集中在 agent 层——模型调用、工具执行、对话管理。在此之上缺少一个控制平面：跨机器调度不同 agent、会话的断开与恢复、多会话管理。

目标用户：日常使用 agentic coding 工具完成开发任务的工程师。工作中同时使用 IDE、浏览器、终端，amux 作为控制平面与这些工具配合，不替代它们。

典型工作环境：用户拥有本机 PC 和远程机器。本机负责浏览器操作（如 UI 测试、网页交互）、轻量开发任务；远程机器负责部署、编译等重任务。amux 统一调度两端的 agent。

核心体验：用户打开 amux，自动恢复所有机器的活跃会话列表；选中会话进入多面板视图，实时看到 agent 交互；随时关闭应用，agent 继续运行；重新打开自动重连，常用操作一键触发，无需打字。

## 2. 用户场景

**创建与管理会话**：用户在机器 A 上启动一个 codex 会话，工作目录为 `~/projects/api-server`。会话列表中出现该会话，标记为"thinking"状态。用户可以实时看到 agent 的思考过程、工具调用和输出。

**关闭后继续运行**：用户关闭 amux，机器 A 上的 agent 继续运行。用户在另一台设备上打开 amux，自动重连，跳到该会话的最新位置，可向上滚动查看关闭期间产生的输出。

**跨机器工作流**：用户在远程机器上用 codex 实现功能，完成后自动在本机用 claude code 做 code review，结果汇总展示。

## 3. 功能需求

### 3.1 会话管理

会话分两类，统一出现在会话列表：

**agent 会话**——在各机器上由对应 agent（codex / claude code / kimi code 等）运行，由该机器 server 持有：

- 新建会话时指定工作目录，agent 即在该目录启动
- 可在 agent 工作过程中发送新指令干预其行为（steer）；可随时取消当前工作
- 关闭应用后 agent 在后台继续运行，重新打开自动重连恢复

**编排 agent 会话**——工作流会话，由 GUI 内置编排 agent 驱动：

- 由工作流创建，其下挂载工作流所驱动的若干 agent 会话（子会话，默认折叠、可展开查看）
- 执行中可随时**暂停 / 继续 / 介入**（向编排 agent 或子会话发送指令）
- 状态持久化于 GUI 本地，GUI 重新打开后恢复编排

两类会话共同：

- 会话有**标题**：默认由首条指令/目标自动生成（简短摘要），用户可随时修改
- 展示 agent 输出（完整消息，非流式）；进行中显示工作状态，思考过程、工具调用等详细活动在活动视图查看
- 结束会话后历史保留，可恢复继续；可永久删除（历史一并移除，不可恢复）
- 浏览所有机器上的所有活跃会话

### 3.2 会话记录（历史与活动）

会话的全部事件（**消息事件**与**活动事件**）按时间排序持久化，统一回溯，作为各视图的数据来源：

- **消息视图**（对话流）：用户消息与 agent 完整输出
- **活动视图**：thinking / tool call / compaction 等过程活动
- 活动按时间线排列，可查看每次活动的细节（如工具调用的参数与结果、思考内容、压缩摘要）；**同类连续事件合并为一条**——thinking 逐块累积为一条持续增长的思考活动，同一工具的多次调用更新合并为一条工具调用活动
- 滚动回溯任意历史位置；回溯期间新事件正常收取但不强制滚动到底，可一键跳回底部
- 重连后自动拉取持久化历史，关闭期间产生的输出不丢

### 3.3 机器管理

- 每台机器都可接入 amux，注册后即可连接使用
- 所有机器（含桌面应用所在的本机）同等对待，不设特殊的本机路径
- 查看所有已注册机器的列表及在线状态
- 每台机器自动发现本机已安装的 agent
- 用户可为 agent 配置默认模型（agent 可执行路径自动发现，不手动指定）
- 查看每个 agent 安装的 skills 列表
- 同一用户可在多台设备同时打开 amux（如台式机和笔记本），多实例天然共存、互不踢出，均可查看和操作同一会话

### 3.4 快捷指令

- 预设常用指令：Commit & Push、Submit PR
- 用户可增删指令、修改指令对应的提示词（每个指令即一段"发给 agent 的提示词"）

### 3.5 Diff Review

- 会话中实时查看当前工作区 git diff——文件列表和行数统计
- 点击文件查看 side-by-side 或 inline diff，带语法高亮
- 对单个文件、单个 hunk 或全部变更执行 revert
- 在 diff 视图中选中特定代码片段，直接向 agent 发送指令

### 3.6 Skills 管理

- skills 注册表只存储**一段描述**：可以是仓库 / 资源 URL，也可以是下载与安装的方法说明
- 给某个 agent **安装 / 更新** skills 时：启动一个新会话（对应机器与 agent），发送提示词让 agent 自己下载、安装或更新 skills
- 用户可查看 skills 列表、新增、编辑描述、删除

### 3.7 工作流

工作流是多步编排：用户用一段**自然语言**描述完整的执行计划（含目标、步骤偏好、机器/agent 偏好、约束），创建**编排 agent 会话**由 GUI 内置编排 agent 执行。工作流不设独立状态机——进展由编排 agent 会话内容与状态（idle / thinking）体现，用户自行判断。工作流复用会话、steer 与多机器能力。

- **内置编排 agent**：GUI 内置（模型可配置），只做编排、不做具体实现——把自然语言工作流拆解为步骤，为每步选择机器与 agent（或沿用用户指定），创建/复用会话并下发指令，依据各步结果决定后续步骤（含按结果分支、重试、汇总结论）；具体编码/执行仍由被调度的 agent 会话完成
- **API 配置前置**：创建编排会话前需在设置「编排 agent」中配置；未配置时界面给出提示并引导到设置页，不创建不可用的会话；运行期 LLM 调用失败（网络 / 鉴权等）以系统消息写入编排会话对话历史，用户可见且随持久化保留
- **自然语言描述**：以一段自然语言描述工作流，支持 @ 引用仓库/文件/目录作为上下文，如"使用 xxx 远程机器的 codex 实现功能并提交推送分支，然后使用本机的 claude code 拉取代码并审查，并将审查意见给到 xxx 远程机器的 codex，直至审查通过，然后通知人类审查，审查通过后，最终由本机 kimi code 来操控浏览器创建 PR"
- **工作流模板**：常用工作流可保存为模板（名称 + 自然语言描述），创建新会话/工作流时可选择"从模板创建"；模板在设置页管理，支持查看 / 新建 / 编辑 / 删除
- **自动推进**：工作流描述本身即完整执行计划，无需确认——编排 agent 每轮决策一次：下达指令后即结束该 turn（不阻塞等待子 agent 结果）；子 agent 会话变为 idle 时，系统自动向编排 agent 会话输入一段 prompt（含子会话完成情况），触发其评估结果并推进下一阶段（分支 / 重试、汇总、启动下一步）
- **进展展示**：工作流所驱动的 agent 会话作为**子会话**挂在工作流会话下（左侧列表默认折叠），每步可下钻查看；进展由编排 agent 会话内容与状态（idle / thinking）体现，用户自行判断
- **暂停 / 继续与介入**（任意时刻，均为向会话发送指令）：
  - **暂停 / 继续**：向编排 agent 会话发送"暂停 / 继续"指令，由编排 agent 控制子 agent 的推进与恢复
  - **介入**：向编排 agent 会话发送新指令调整后续动作，或向某步关联的 agent 会话发送指令直接干预该步执行
- **持久化与恢复**：编排 agent 会话状态持久化于 GUI 本地，子会话由各机器 server 持久化；GUI 关闭后自动推进停止（自动触发在 GUI 侧），已下发的子会话由各机器 server 继续运行；GUI 重新打开后依据子会话当前状态恢复自动推进

## 4. 交互设计

### 4.1 主界面布局

#### 4.1.1 会话列表（左侧面板）

- 包含 agent 会话与编排 agent 会话，按**最近活跃**排序
- 基于工作流创建的编排 agent 会话，其下挂载工作流所驱动的若干 agent 会话（子会话），**默认折叠**、可展开查看；子会话随父会话一起参与最近活跃排序
- 每条显示**会话标题**、agent、所属机器；**工作中**以转圈表示、空闲无转圈（会话状态只区分工作/空闲）
- **右键点击会话**弹出操作菜单：**删除**（永久删除、历史一并移除，弹窗确认）与**重命名**（行内修改标题）
- 顶部**「+」按钮**进入新会话视图（新建会话 / 工作流）；底部为**设置入口**，点击打开设置浮窗

#### 4.1.2 新会话视图（未选中任何会话时）

- 顶部为模式切换：**普通** / **工作流**
- **普通**模式：选择机器与 agent（并列一排）、指定工作目录，点击**创建会话**——只创建会话并跳转到会话交互页，首条指令由用户在会话页的输入区发送
- **工作流**模式：从模板创建（选择模板）或直接输入自然语言执行计划，创建编排 agent 会话

#### 4.1.3 会话视图与输入（中间面板，选中会话后）

- 中间面板**上下分栏**：
  - **上方：对话流**——只展示用户消息与 agent 输出的消息气泡（输出为完整消息，非流式），弹性占满剩余空间
  - **下方：会话活动**——只展示**正在进行的活动**（一条或无）：当前 thinking / tool call 的实时状态，空闲时不显示；完整历史在右侧面板查看
  - thinking 活动**流式传输**：逐块累积为一条持续增长的实时活动（合并推送），而非每次块产生一条新活动
- 底部：输入区；输入区上方为快捷指令栏（Commit & Push、Submit PR 等）
- 对话流右侧边缘：竖向排列的悬浮按钮（diff、会话详情、会话活动历史），点击展开对应的右侧面板

#### 4.1.4 上下文面板（右侧面板）

- 默认折叠，由悬浮按钮触发展开；展开时**窗口向右扩展**（中间面板宽度不变），关闭时收回
- **diff 视图**：点击 diff 按钮弹出工作区 diff 视图（workspace 不是 git 仓库时不提供 diff 按钮）
- **会话详情**：点击会话详情按钮弹出会话信息
- **会话活动**：点击会话活动按钮弹出会话活动，视图上下滚动查看更久的会话活动

### 4.2 输入

- 输入区支持多行文本，可拖拽文件、粘贴图片作为上下文
- 支持语音输入
- 支持 @ 引用文件或目录作为上下文

### 4.3 设置页面

- 全局配置集中在**设置浮窗**，经左侧面板底部的设置入口打开；浮窗以半透明遮罩盖在主界面之上，内部为**分类导航侧边栏 + 右侧设置内容**（类似系统设置），点遮罩或关闭按钮收起
- 设置浮窗分类：
  - **机器管理**：接入 / 移除机器、连接配置（地址、token）、agent 默认模型、查看每个 agent 的 skills 列表
  - **编排 agent**：内置编排 agent 的 API 配置——API Backend（包含 chat_completions 和 messages）、Base URL、API key、**模型**（调用的 LLM 模型名，如 gpt-4o-mini；OpenAI 兼容 API 的请求必须指定模型）
  - **快捷指令**：指令自定义（增删指令、修改提示词）
  - **Skills**：skills 描述注册表
  - **工作流模板**：模板管理（查看 / 新建 / 编辑 / 删除）；模板是可复用的自然语言工作流描述

## 5. 边界与约束

- 不做 agent 实现，只做控制平面——amux 只是连接已有的 agent；GUI 内置的编排 agent 只负责工作流的拆解与调度，不参与具体的编码/执行
- 不做 IDE 插件——amux 是独立桌面应用
- 不替代 git 工具——不提供完整的 git 操作界面，只提供常用 git 操作
- 不做代码编辑器——代码查看仅限于 diff review 场景
- 不做用户认证与权限系统——单用户工具，信任运行环境
