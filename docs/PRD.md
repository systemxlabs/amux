# amux — Product Requirements Document

> 本文档描述 amux 的**完整产品**，不区分优先级。agent 依据本文档实现代码；本文档变更时，代码随之同步更新（见 AGENTS.md「文档与实现」）。

## 1. 背景与目标

当前的 agentic coding 工具（Codex、Claude Code 等）集中在 harness 层——模型调用、工具执行、对话管理。在此之上缺少一个控制平面：跨机器调度不同 harness、会话的断开与恢复、多会话管理。

作者是 herdr 的用户。herdr 是一个终端原生的 agent 多路复用器：在单个 TUI 中管理多个 agent 会话，以 workspace / tab / pane 三级层级组织，每个 pane 是真实的 PTY 终端。herdr 解决了"同时跑多个 agent 时切来切去很乱"的问题，但有两个局限：1) TUI 交互不如 GUI（例如需要反复打字执行常用 git 操作，而 GUI 可以一键按钮完成）；2) 只能管理本机 agent，不支持跨机器调度。amux 的目标是做一个 GUI 桌面产品，在单一面板中统一调度不同机器上的不同 harness 完成工作。

产品定位：个人工具，不做 SaaS。

参考产品：
- herdr：终端原生 agent 多路复用器，单 TUI 管理本机多 agent（workspace/tab/pane），PTY 真终端，detach/reattach，Socket API 支持 agent 间编排
- codex app：桌面 agent 应用的会话设计，消息气泡、内嵌 diff 展示等交互模式值得参考

目标用户：日常使用 agentic coding 工具完成开发任务的工程师。工作中同时使用 IDE、浏览器、终端，amux 作为控制平面与这些工具配合，不替代它们。

典型工作环境：用户拥有本机 PC 和远程机器。本机负责浏览器操作（如 UI 测试、网页交互）、轻量开发任务；远程机器负责部署、编译等重任务。amux 统一调度两端的 harness。

核心体验：用户打开 amux，自动恢复所有机器的活跃会话列表；选中会话进入多面板视图，实时看到 agent 交互；随时关闭应用，agent 继续运行；重新打开自动重连，常用操作一键触发，无需打字。

## 2. 用户场景

**创建与管理会话**：用户在机器 A 上启动一个 codex 会话，工作目录为 `~/projects/api-server`。会话列表中出现该会话，标记为"thinking"状态。用户可以实时看到 agent 的思考过程、工具调用和输出。

**关闭后继续运行**：用户关闭 amux，机器 A 上的 agent 继续运行。用户在另一台设备上打开 amux，自动重连，跳到该会话的最新位置，可向上滚动查看关闭期间产生的输出。

**Steer 干预**：Agent 正在执行任务时，用户发送"别改测试文件"。Agent 收到后调整行为，用户无需等待当前工作结束。

**跨机器工作流**：用户在远程机器上用 codex 实现功能，完成后自动在本机用 claude code 做 code review，结果汇总展示。

**本机浏览器测试**：Agent 在本机自动打开浏览器执行 UI 测试，用户在 amux 中看到 agent 的工具调用和结果输出，同时在本机浏览器中观察实际页面操作。

## 3. 交互设计

### 3.1 GUI 布局

多面板设计，参考 codex app 的消息气泡和 diff 内嵌展示：

- 左侧面板：机器与会话列表，按机器分组，显示每个会话的状态和最近输出摘要
- 中间面板：当前选中会话的对话流，消息气泡展示 agent 的文本输出、思考内容、工具调用
- 右侧面板：上下文面板，默认展示当前工作区 diff，可在 diff 和会话详情之间切换

### 3.2 输入

- 输入区支持多行文本，可拖拽文件、粘贴图片作为上下文
- 支持语音输入
- 支持 @ 引用文件或目录作为上下文

### 3.3 交互原则

- 常用操作用按钮代替打字：commit、push、submit PR、undo 等均可一键触发，无需在 prompt 中输入 git 命令
- 按钮可自定义：用户可增删按钮、修改按钮对应的提示词
- Agent 自动打开浏览器做 UI 测试时，amux 不内嵌浏览器——用户在系统浏览器中直接观察

## 4. 功能需求

### 4.1 会话管理

- 在多台机器上创建 agent 会话，指定工作目录即可启动
- 支持 codex、claude code、kimi code 等主流 agent harness
- 实时展示 agent 思考过程、文本输出、工具调用
- 可在 agent 工作过程中发送新指令干预其行为（steer）
- 可随时取消当前工作
- 结束会话后对话历史保留，可恢复继续
- 可永久删除会话（历史一并移除，不可恢复）
- 关闭应用后 agent 在后台继续运行，重新打开自动重连恢复

### 4.2 会话历史

- 会话对话内容持久化存储（用户输入、agent 思考、工具调用、agent 输出）
- 用户可滚动回溯任意历史位置
- 回溯期间新事件正常收取但不强制滚动到底，用户可一键跳回底部
- 支持从历史中选中内容复制
- 重连后自动拉取持久化历史，关闭期间产生的输出不丢

### 4.3 多机器管理

- 每台机器都可接入 amux，注册后即可连接使用
- 所有机器（含桌面应用所在的本机）同等对待，不设特殊的本机路径
- 查看所有已注册机器的列表及在线状态
- 每台机器自动发现本机已安装的 agent harness
- 用户可为 harness 配置默认模型（harness 可执行路径由 driver 自动发现，不手动指定）
- 浏览所有机器上的所有活跃会话，按机器或 harness 类型筛选
- 同一用户可在多台设备同时打开 amux（如台式机和笔记本），多实例天然共存、互不踢出，均可查看和操作同一会话

### 4.4 通知

- 工作结束（含结束原因）、异常终止、长时间无响应时发送桌面通知
- 按会话或全局配置通知开关和触发条件
- 通知携带机器和会话信息，点击通知可直接打开对应会话

### 4.5 快捷按钮

- 预设常用操作：Commit & Push、Submit PR
- 用户可增删按钮、修改按钮对应的提示词（按钮即"发给 agent 的指令"）

### 4.6 Diff Review

- 会话中实时查看当前工作区 git diff——文件列表和行数统计
- 点击文件查看 side-by-side 或 inline diff，带语法高亮
- 对单个文件、单个 hunk 或全部变更执行 revert
- 在 diff 视图中直接对特定代码片段发起指令

### 4.7 Worktree 管理

Session 在工作目录中原地工作，不自动创建 worktree。Worktree 管理是独立功能：

- 查看任意机器上所有 git worktree 的信息：路径、分支、clean/dirty 状态
- 从分支或 commit 创建新 worktree，可同时创建关联 agent 会话
- 删除 worktree，有活跃会话时警告
- 锁定 worktree 防止误删

### 4.8 Skills 管理

- 添加 skills 时只需指定仓库 URL 和本地目录，系统只存这两项
- 会话启动时，系统将已启用的 skills 拼成 prompt 发给 agent，由 agent 执行实际的 clone/pull
- Skills 可设为全局、项目级（关联特定 git repo 的会话自动加载）、或个人级
- 每个 skills 仓库可单独启用/禁用

### 4.9 工作流

工作流是一个可复用的模板。用户以自然语言描述需求，由 agent 生成模板（任务拆分、依赖关系、机器/harness 分配），用户确认后保存。

- 使用场景：既支持工作流驱动模式，也支持手动起会话的临场发挥模式，两者并存
- 模板创建：自然语言描述 → agent 生成 → 用户审核保存。预计日常使用 3-5 个模板
- 任务间上下文：上游任务的输出自动作为下游任务上下文的一部分；下游任务的 agent 可读取上游完整会话历史
- 触发方式：先仅支持手动触发
- 并发：允许多个工作流实例同时执行
- 人类审查：工作流中可指定某个任务需要人工审查——任务完成后暂停，等待用户审核确认/驳回后继续；驳回时可附带反馈重新执行
- 失败处理：用户可配置每个任务的失败策略——等待手动重试、跳过继续、或取消后续
- 工作流中每个任务是一个 agent 会话，执行后可回溯各任务的完整会话历史
- 预置模板（实现+Review、多模型对比、CI 修复、代码迁移）供快速上手，支持导出/导入

## 5. 非功能需求

- **响应性**：打开应用 3 秒内恢复连接并展示会话列表；实时事件延迟不超过 500ms
- **可靠性**：关闭应用后 agent 不中断；机器重启后重新打开 amux 即可恢复会话
- **跨平台**：macOS、Linux 一级支持；Windows 二级支持
- **数据主权**：所有数据存储于自有机器，不上传至第三方服务

## 6. 边界与约束

- 不做 agent 实现，只做控制平面——amux 只是连接已有的 agent harness
- 不做 IDE 插件——amux 是独立桌面应用
- 不替代 git 工具——不提供完整的 git 操作界面，只提供常用快捷操作
- 不做代码编辑器——代码查看仅限于 diff review 场景
- 不做用户认证与权限系统——单用户工具，信任运行环境
